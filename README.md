# Win11
## File Explorer list engine, step 4 (parts 4.1 - 4.14 and 4.15.1 - 4.15.5, step 4 finished)

- **4.1 Groundwork:** `FileItem` (`FileItem.kt`) is one immutable row: file, name, path, `isDir`, lower-case `ext`, `hidden`, `size`, `modified`. Every disk stat is read once, on a worker thread, so scrolling never touches the file system. `RecyclerView` 1.3.2 was already a dependency (Messages and Notification settings use it), nothing to add. The only `ListView` of the explorer was in `ExplorerUi`.
- **4.2 Background loader:** `FolderLoader` (`FolderLoader.kt`) runs `listFiles()`, sorting (folders first, then A-Z, case-insensitive) and the free / total space lookup off the main thread. Starting a new load, or `cancel()`, drops every older one, so a slow folder can never replace the folder opened after it. Results: `Content`, `Denied` (permission), `Failed`. The loading state appears only if a folder takes longer than about 150 ms. `ExplorerUi.load()` is the entry point, `retry()` repeats the last load, `destroy()` stops the threads.
- **4.3 RecyclerView base:** the explorer list is now a `RecyclerView` (`LinearLayoutManager`) in `FileExplorerUi.kt`.
  - **`ExplorerAdapter`** has three row types: the **drive card** is row 0 (it was `addHeaderView`, still scrolls with the list), the **files and folders** follow, and the **empty / loading / error box** is the last row (it was `addFooterView`). The same views are reused, only wrapped.
  - **`ItemVH`** (ViewHolder) holds one row. Click, long-click and the `⋮` button are wired once in the holder and look the item up by its position when pressed. **Behaviour is unchanged:** tap a folder opens it, tap a file opens it (`onItemClick`), long-press or `⋮` opens the item menu (`onItemMenu`). The row look is unchanged (`⋮` and `›` text, name, date, size, "N items"); the glass row and vector icons came in part 4.4 (below).
  - **`DiffUtil`:** when the **same folder** is loaded again (after delete, rename, new folder) the difference is calculated on a worker thread (`explorer-diff`) and only the changed rows are inserted, removed or refreshed; the scroll position stays. Opening a **different folder** swaps the list at once, without animation, and starts at the top. Rows are the same when the path is equal; their content is the same when the whole `FileItem` (size, date, ...) is equal. A newer list or a loading / error state throws away a diff that is still running.
  - **Folder item counts** ("12 items") still load in the background. When counts arrive, only the "date  •  N items" text of the rows on screen is refreshed (payload update, no icon flicker, no change animation). Redraws are still merged into one every 60 ms.
  - **Fast scroll:** `ListView` had a built-in fast scroller, `RecyclerView` has none, so `FastScrollBar` (a small view on top of the list) shows a thumb while you scroll a long list (more than two screens), fades it out after about 1.2 s, and the thumb can be dragged by its right-edge handle (it turns blue while dragged). Touches elsewhere go to the list. Part 4.15 will tune it on 5000+ files.
  - `ExplorerUi.destroy()` also stops the diff thread. Public API of `ExplorerUi` (`load`, `retry`, `cancelLoad`, `show`, `destroy`) and everything in `FileManagerUi.kt` / `MainActivity.kt` are unchanged.
- **4.4 List row, glass design:** only the look of one file / folder row changed (`Row` in `FileExplorerUi.kt`); everything behind it is as in 4.3.
  - **Glass card:** each row is a rounded card (12dp corners) with a soft white fill (`WX.GLASS`, `#14FFFFFF`), a 1dp light edge (`WX.GLASS_EDGE`, `#1FFFFFFF`) and a 12dp / 3dp margin around it, so rows are separate cards on the dark content area. Touch ripple follows the rounded corners.
  - **Icon tile:** the file / folder icon (`FileIconView`, unchanged drawing) sits on a 44dp rounded glass tile (10dp corners). The tile is tinted with the file-type colour at about 14% (`fileTypeColor(ext)`); folders get an amber tile (`FOLDER_TILE`). Hidden files (name starts with `.`) keep the dimmed icon and now also a slightly dimmed name.
  - **Vector icons instead of text:** `RowIconView` (new, `FileExplorerUi.kt`) draws the folder arrow (**chevron**, rounded stroke, same path as `ic_w_chevron_right`, 18dp, folders only) and the **more** button (three vertical dots, 22dp icon inside a 44dp round touch area). The text glyphs `›` and `⋮` are gone from the row. The icons are drawn from path data like `VectorIconView`, so no new drawable resource is needed and `Win11Shell.kt` is untouched.
  - **All details kept:** name (single line, middle ellipsis, now medium weight), second line "date  •  size" for files and "date  •  N items" for folders (N still loads in the background and only that text is refreshed), `More options` content description, row height at least 64dp.
  - **Behaviour unchanged:** tap a folder opens it (`onOpenFolder`), tap a file opens it (`onItemClick`), long-press on the row or tap on the more button opens the item menu (`onItemMenu`). Holder wiring (`ItemVH`), `DiffUtil` (row identity = path, content = whole `FileItem`), payload update for counts, fast-scroll bar, loading / error / empty box, drive card and the whole public API of `ExplorerUi` are the same as in 4.3.
  - The address-bar breadcrumb separator `›` (not part of the list rows) is still a text glyph; it is not changed here.
- **4.5 Grid mode:** the explorer can now show its items as a grid. All in `FileExplorerUi.kt`.
  - **API:** `enum class ExplorerViewMode { LIST, GRID }`, `ExplorerUi.viewMode` (read) and `ExplorerUi.setViewMode(mode)`. The default is still **LIST**, so nothing changes on screen until a caller switches. The toggle button, saving the choice and the switch animation are part 4.7. Until then it can be tried with one line, for example `explorerUi.setViewMode(ExplorerViewMode.GRID)` after creating the `ExplorerUi` in `FileManagerUi.kt`.
  - **`GridLayoutManager`:** one list and one grid layout manager are kept and swapped. The same adapter serves both: the drive card (row 0) and the empty / loading / error box (last row) take the **whole row** (`SpanSizeLookup`), files and folders take one column. Switching keeps the same items and the first visible item stays first. `DiffUtil` updates, folder counts, loading / error states and the fast-scroll bar work the same in both modes.
  - **Columns by screen width:** columns = list width / 120dp, at least 2, at most 8 (a normal phone gives 3, a landscape phone or tablet more). The width is checked on every layout, so rotation and split screen change the column count by themselves (`updateColumns`).
  - **Grid cell (`Cell`, holder `GridVH`):** a glass card (same glass look as the 4.4 row via the shared `glassRipple()`), a 76dp icon tile with the 44dp file / folder icon (same tint rule as the list: file-type colour at about 14%, amber for folders), the **more** vector button (three dots) in the tile corner, then the name (one line, middle ellipsis), a size line (files) or "N items" line (folders; shows "Folder" until the background count arrives), and the date. Hidden files stay dimmed. Spacing (`GridGap`): 4dp between cells, 12dp at the screen edges, like the list rows.
  - **Behaviour unchanged:** tap a folder opens it, tap a file opens it, long-press on the cell or tap on the more button opens the item menu (same callbacks as in the list).
  - Row views of the two modes are different view types (`VT_ITEM` list row, `VT_GRID` grid cell), so they never mix in the recycle pool.
- **4.6 Large-thumbnail mode:** `ExplorerViewMode.LARGE` (third mode). Big preview card (`LargeCard`, holder `LargeVH`, view type `VT_LARGE`): a tall rounded preview area (`RatioFrame`, ratio 0.8) with the file / folder icon on the tinted tile, a file-type chip in the bottom corner, a round dark **more** button in the top corner (readable on a bright photo), then name, size / "N items" and date. Columns = list width / 170dp, at least 2, at most 5 (two big cards on a phone). Same data, callbacks and `GridGap` spacing as the grid.
- **4.7 View-mode switcher:** three buttons (List / Grid / Large, `ModeIconView`) in the command bar; the active one is accent coloured on a soft pill (`updateSwitcher`). The choice is saved (`SharedPreferences` `explorer_ui`, key `view_mode`) and restored when the explorer opens. With `setViewMode(mode, animate = true)` the items fade out (90 ms), the layout changes, then fade in with a slight zoom (180 ms); the first visible item stays first.
- **4.8 Thumbnail cache engine:** the engine only, in the new `ThumbCache.kt`. It does not know how to make a picture; decoders do that (4.9 - 4.11) and plug in with `ThumbLoader.register(decoder)`. **With no decoder registered nothing is requested and every item keeps its file icon, so 4.8 alone changed nothing on screen; the first decoder (images) came in 4.9.**
  - **`ThumbMemory`:** one shared `LruCache<String, Bitmap>` counted in real bitmap bytes (`allocationByteCount`): 1/6 of the app heap, at least 12 MB, at most 64 MB. Shared by all loaders, so a new `ExplorerUi` (rotation) starts with the pictures already made. Shrinks by itself: `onTrimMemory` >= RUNNING_LOW halves it, >= BACKGROUND clears it, `onLowMemory` clears it (registered once per process). Bitmaps are never recycled by hand, a view may still be drawing one. A second small `LruCache` (1024 keys, `misses`) remembers files whose decoder returned "no picture", so a broken file is not decoded again on every scroll.
  - **Key:** `path | lastModified | size | wanted edge px`. An edited file gets a new key; each mode asks for its own size (`THUMB_LIST_DP` 48, `THUMB_GRID_DP` 112, `THUMB_LARGE_DP` 180).
  - **`ThumbLoader` (thread pool):** 2 - 4 daemon threads (CPU count - 1) at background priority, one loader per `ExplorerUi`. The queue is **newest first** (`LinkedBlockingDeque.addFirst`), so while the user flings through a folder the rows on screen now are made before the ones already scrolled past. Before decoding, a worker checks the cache again (another request may have made it meanwhile). Decoder exceptions are caught; an `OutOfMemoryError` clears the bitmap cache and is not remembered as "no picture". A job that was cancelled while decoding is still cached but not delivered.
  - **`ThumbRequest` / cancel:** every job can be cancelled from any thread; a cancelled job is removed from the queue, or, when it is already decoding, its result is dropped. Results reach the view on the main thread only if the request was not cancelled.
  - **`ThumbDecoder`:** `supports(item)` (cheap, extension only) and `decode(item, edgePx, req)` (worker thread; check `req.cancelled` between heavy steps; return null for "no picture"). The first decoder that supports a file wins. Since 4.9 `edgePx` means the **short side** of the picture (the views are `CENTER_CROP`), the long side stays within 2 x `edgePx`.
  - **`ThumbSlot` (one per Row / Cell / LargeCard):** `bind(item, edgePx)` from the holder's `bind()`: folders and unsupported files clear the slot; a picture in memory is shown at once (no animation); otherwise **the file icon stays as the placeholder** and a request is queued, and when it arrives the picture fades in (150 ms) over the tile and the icon is hidden. A payload re-bind (folder count arrived) does not touch a picture that is already showing, so there is no flicker. `clear()` cancels the request and removes the picture.
  - **Recycling:** `ExplorerAdapter.onViewRecycled` calls `recycle()` on the holder's view, so a recycled row stops waiting for the picture of the file it showed before and can never show or receive it. A re-bind to another file cancels the old request first.
  - **Views:** the list tile (44dp) and grid tile (76dp) get a `CENTER_CROP` `ImageView` layer (hidden until a picture arrives) with rounded 10dp clipping (`clipRound`); in the grid the more button sits above the picture and turns into the dark round style with white dots while a picture is shown (as on the large card). The large card uses its existing `thumb` layer; its type chip and more button stay above the picture.
  - **Lifecycle:** `ExplorerUi.destroy()` calls `thumbs.shutdown()` (stops the threads, drops the queue; the shared bitmap memory stays).
- **4.9 Image thumbnails:** the first decoder, `ImageThumbDecoder` in the new `ImageThumbs.kt`. It is registered once in `ExplorerUi` (`ThumbLoader.register(ImageThumbDecoder)`, right after the loader is created), so from now on image files in List, Grid and Large mode show their own picture instead of the file icon; the icon stays as the placeholder until the picture is ready, then the picture fades in (4.8 behaviour, unchanged).
  - **Files:** `jpg`, `jpeg`, `jpe`, `png`, `webp`, `gif` (first frame), `bmp`, `heic`, `heif` (HEIC / HEIF only where Android can decode them, API 28+; otherwise `null` and the icon stays, remembered in the "no picture" list). SVG and RAW are not decoded and keep the file icon. Empty (0 byte) files and files whose size cannot be read return `null`.
  - **`inSampleSize`:** step 1 reads only the picture size (`inJustDecodeBounds`, no pixels). Step 2 works out the wanted size: the **short side is about `edgePx`** (the tile is `CENTER_CROP`, so the short side must fill it, otherwise a wide picture would be enlarged and blurry), the **long side is capped at 2 x `edgePx`** so a panorama cannot eat the memory; a picture smaller than that is **never enlarged**. Step 3 decodes with the biggest power-of-two `inSampleSize` that is still not below the wanted size, so a 12 MP photo is never fully loaded. Step 4 scales to the exact size (bilinear) when the sampled bitmap is still bigger. The temporary bitmaps made inside the decoder are recycled at once (they were never shown); the returned bitmap belongs to the cache and is never recycled by hand.
  - **EXIF rotation:** for `jpg / jpeg / jpe / webp / heic / heif / png` the orientation tag is read (`android.media.ExifInterface`, framework class, no new dependency) and all eight orientations are fixed: rotate 90 / 180 / 270, flip horizontal / vertical, transpose, transverse. The scaling comes first and the rotation after it, so only the small bitmap is rotated. A missing or unreadable tag (or a normal orientation) costs nothing and leaves the picture as it is.
  - **Cancel:** `req.cancelled` is checked after the size read, after the decode and after the scaling; a recycled row stops the work early and its half-made bitmap is recycled. A decode failure (broken file) returns `null`; `OutOfMemoryError` is handled by the engine (4.8: bitmap cache cleared, not remembered as "no picture").
  - **Cache sizes** (unchanged, 4.8): List 48dp, Grid 112dp, Large 180dp, so each mode gets (and caches) its own picture size; an edited file has a new key (date + size) and is made again.
- **4.10 Video thumbnails (this step):** the second decoder, `VideoThumbDecoder` in the new `VideoThumbs.kt`, registered next to the image decoder in `ExplorerUi` (`ThumbLoader.register(VideoThumbDecoder)`). Video files now show a frame instead of the file icon in List, Grid and Large mode (icon first, then the picture fades in, as in 4.8), with the **duration badge** in the corner.
  - **Files:** `mp4`, `m4v`, `mkv`, `webm`, `3gp`, `3gpp`, `3g2`, `mov`, `avi`, `flv`, `wmv`, `mpg`, `mpeg`, `ogv`. What Android cannot play (some `avi` / `wmv` / `flv`) returns `null`, keeps the file icon and is remembered in the \"no picture\" list. `ts` is **not** listed on purpose (in a file manager it is almost always TypeScript). Empty (0 byte) files return `null`.
  - **The frame:** `MediaMetadataRetriever` (`setDataSource(path)`), the frame at about **1 s** (the very first frame is often black); a video shorter than 2 s uses its middle. `OPTION_CLOSEST_SYNC` (nearest key frame) is used because it is much faster than an exact frame. If that gives nothing, the plain `getFrameAtTime()` is tried. The retriever is always `release()`d (in `finally`), also when cancelled or broken; any exception means \"no picture\".
  - **Memory:** on Android 8.1+ (API 27) `getScaledFrameAtTime` decodes the frame **already at the wanted size**, so a 4K video never makes a 4K bitmap. The video size is read from the metadata with the **rotation** applied (`VIDEO_ROTATION` 90 / 270 swaps width and height). The scaled result is checked: if its shape differs from the video's shape by more than 5% (devices handle rotation differently), it is thrown away and the plain full frame is taken and scaled down instead. On Android 7.x (API 24 - 26) the full frame is taken and scaled down (the full frame is recycled at once). `req.cancelled` is checked after opening the file and after each frame.
  - **Size rule shared with images:** the new top-level `thumbTargetSize(w, h, edgePx)` (in `ImageThumbs.kt`; the image decoder now uses it too, same result as in 4.9): short side about `edgePx`, long side at most 2 x `edgePx`, never enlarged.
  - **Duration badge:** the decoder reads the duration in the same pass and stores it in the new `ThumbMemory.durations` (`LruCache<String, Long>`, 4096 keys, same key as the picture; it is cleared by `ThumbMemory.clear()` but not trimmed with the bitmaps, it is tiny). `ThumbSlot` got an optional `badge: TextView?`: when a picture is shown it fills the badge from `durations` and shows it (fades in together with the picture); when the slot is cleared / recycled / re-bound the badge is hidden, and for pictures without a duration (images) it stays hidden. `formatDuration(ms)` gives `m:ss` (`h:mm:ss` from one hour, rounded to the nearest second, at least `0:01`). The badge is a white bold text on a dark rounded pill (`durationBadge()` in `FileExplorerUi.kt`) in the **bottom-end corner**: 8sp on the 44dp list tile, 10sp on the grid tile (the more button is top-end), 11sp on the large card (the type chip is bottom-start).
  - A payload re-bind (folder count arrived) does not touch the picture or the badge that are showing, so there is no flicker.
- **4.11 APK, audio and PDF thumbnails:** three more decoders in the new `ApkAudioPdfThumbs.kt`, registered next to the image and video decoders in `ExplorerUi` (`ThumbLoader.register(...)`; `ThumbEnv.app` gives the APK decoder a `PackageManager`). `ApkThumbDecoder` shows the real icon of the APK (read from the file, the app does not have to be installed) on a square bitmap with a small margin so `CENTER_CROP` never cuts it; `AudioThumbDecoder` shows the album art embedded in the file (`MediaMetadataRetriever.embeddedPicture`, decoded with `inSampleSize` like images); `PdfThumbDecoder` renders the first page (`PdfRenderer`) on a white background at the wanted size. A file without an icon / cover, an encrypted or broken PDF returns `null`, is remembered in the "no picture" list and keeps its normal file icon (fallback). All three check `req.cancelled` between heavy steps and use the shared `thumbTargetSize`.
- **4.12 Folder icon and item count:** `FolderCount.kt` (`FolderCountMemory`, `FolderCounter`, `FolderCountSlot`) counts the items of a folder in the background. One shared `LruCache` (4096 keys, key = `path|modified`, so a stale number is never shown after the folder changed) keeps the numbers across rotation and new `ExplorerUi` instances. One low-priority worker counts the **newest request first** (rows on screen before rows already scrolled past), a recycled row cancels its request, results come back on the main thread. Every entry counts (hidden too), no recursion; an unreadable folder gives `COUNT_UNREADABLE`. `folderCountLabel()` gives "Empty" / "1 item" / "N items" (shared by List, Grid, Large). A folder with items gets a paper sheet in its folder icon (`FileIconView.setFolder`); an empty / unknown folder keeps the plain folder.
- **4.13 Shimmer / loading skeleton:** `SkeletonView` in the new `ShimmerSkeleton.kt` replaces the old loading spinner. Ghost items in the shape of the active mode (List row, Grid cell, Large card, same measures as `Row` / `Cell` / `LargeCard`) with one shared light band sweeping over all of them (1.3 s), drawn on a single Canvas. It appears only if a folder takes longer than about 150 ms, fades in (120 ms) and, once shown, stays at least `SKELETON_MIN_MS` (280 ms) so it never just flashes. Switching mode or rotating during a load re-shapes it (`syncSkeleton`).
- **4.14 Glass empty / error states (this step):** the plain "This folder is empty" text and the plain error box are replaced by **one glass state card**, `StateCardView` in the new `GlassStates.kt`. It is still the last row of the list (the old footer), so it scrolls under the drive card and takes the whole row in Grid and Large mode. The card is a rounded glass panel (20dp corners, `WX.GLASS` fill, `WX.GLASS_EDGE` 1dp edge, at most 420dp wide so a tablet or landscape grid keeps a neat card), a 76dp tinted icon tile with a vector icon drawn from path data (`StateIconView`, no drawable resource), a title, a message and pill buttons (accent pill = main action, glass pill = second action, ripple inside the rounded corners). It fades in with a small rise (180 ms); showing the same face again (for example the same empty folder after a reload) does not rebuild or re-animate it.
  - **Empty folder:** amber folder icon, "This folder is empty", "Nothing here yet. Create a folder or copy files into it.", button **New folder** (the same `onNewFolder` callback as the command bar button).
  - **No permission** (`FolderResult.Denied`): orange padlock icon, "Permission denied", "This app isn't allowed to open this folder. Allow storage access and try again." (same text as before), buttons **Allow access** and **Retry**. Allow access (`openStorageAccessSettings`) opens the all-files-access page of this app on Android 11+ (if it is not granted yet) and otherwise the app details page, where the Storage permission can be switched on; then press Retry.
  - **Load failed** (`FolderResult.Failed`): red warning icon, "Couldn't load this folder", the failure message (same as before), button **Retry**.
  - **Unchanged:** `retry()` repeats the last load, a new load / loading skeleton / content hides the card, the empty card is shown only for a folder that loaded with 0 items (the drive card and the "0 items" label stay), `FolderLoader` results, `DiffUtil`, thumbnails, folder counts, the skeleton, the view-mode switcher, fast scroll and the public API of `ExplorerUi` are the same as in 4.13. The card announces itself politely to screen readers (live region) and the buttons have content descriptions.
- **4.15.1 Fast-scroll and scroll performance:** (note written in 4.15.5 from the code) in `FileExplorerUi.kt` and `ThumbCache.kt`.
  - **Row cache:** `setItemViewCacheSize(10)`, so rows just scrolled off stay attached and are not re-bound when the user flicks back a few rows (the default of 2 re-bound almost every row on a direction change). The shared `RecycledViewPool` limits stay: `VT_ITEM` 24, `VT_GRID` 48, `VT_LARGE` 24.
  - **No decodes during a fling:** an `OnScrollListener` calls `thumbs.hold(2500L)` while the list is `SCROLL_STATE_SETTLING` and `thumbs.release()` in every other state, so the workers take no new thumbnail job during a fling and start the waiting ones (newest = visible first) the moment it stops. A job already decoding finishes. Dragging the fast-scroll thumb does the same through `FastScrollBar.dragging`.
  - **`DiffUtil`:** `calculateDiff(callback, false)`, move detection off: much faster on 5000+ files, same result for a sorted list.
- **4.15.2 Big folders (5000 / 10000 / 20000 files):** `FileItem.from` uses ONE `Os.stat` call (type + size + date) instead of three (`isDirectory`, `length`, `lastModified`; on 20000 files that was 60000 system calls); the old `File` calls stay as the fallback (broken link, permission, odd file system). `FolderLoader` splits the stat work over `STAT_THREADS` (3) threads from `PARALLEL_FROM` (1500) entries on (on phone storage a stat mostly waits, so the threads overlap the waiting); the `files` list of a result is lazy, built only if asked. `ExplorerUi.load()` logs the time from tap to list handed to the `RecyclerView` (`ExplorerUi: N files: tap -> list handed ..`) and `FolderLoader` logs its `list / stat / sort` times. Test data: `tools/make_big_folders.sh` (`/sdcard/BigTest/{5000,10000,20000}`).
- **4.15.3 Memory and leak check:** audit of `ThumbMemory`, `ThumbLoader`, `FolderCounter`, `FolderLoader`, `ExplorerUi.destroy()` and the row recycle path. Checked and found fine: bitmap cache size (1/6 heap, 12 - 64 MB, counted in bytes), no `Activity` kept by any `object` (only `applicationContext`), `onViewRecycled` cancels the thumbnail and count request of a row, decoders release `MediaMetadataRetriever` / `PdfRenderer` / file descriptors in `finally`, the skeleton animator stops on detach, `FastScrollBar` removes its callbacks on detach. Fixed:
  - **Good files marked "no picture":** when `shutdown()` interrupted a decode that was running, the failure was stored in `ThumbMemory.misses` (shared by every `ExplorerUi`), so that file kept its plain icon later. Now a decode stopped by shutdown / cancel is never stored as "no picture" (`ThumbLoader.inFlight` marks running jobs cancelled too).
  - **Results after the screen is gone:** `ThumbLoader`, `FolderCounter` and `FolderLoader` `shutdown()` now remove the results already posted to the main thread; a posted result also checks `down` before it runs, so no callback reaches a row (and the Activity) after `destroy()`.
  - **`onTrimMemory`:** the levels 10 - 39 all only halved the cache. Now `RUNNING_LOW` halves it, `RUNNING_CRITICAL` keeps a quarter, `UI_HIDDEN` halves it, `BACKGROUND` and above clear it.
  - **`ExplorerUi.destroy()`:** drops everything queued on its private handler (`removeCallbacksAndMessages(null)`), cancels the running view animations (list, loading box, state card) and logs `ThumbMemory.describe()` (bytes, hits, misses, evictions) to the debug log.
  - **`FolderLoader`:** the extra stat threads (folders of 1500+ entries) catch every error, so one odd file can no longer crash the app through an uncaught thread exception.
  - Not changed on purpose: bitmaps are still never recycled by hand; `misses` / `durations` / folder counts stay untrimmed (a few KB).
- **4.15.4 Rotation and config changes:** audit of what happens when the window changes (rotation, split-screen, fold / unfold, dark / light) with `MainActivity` handling the change itself (`android:configChanges`). Checked by reading the code (see "Not verified here"). Found fine: `MainActivity.onConfigurationChanged` keeps the Activity alive, so the open folder, the scroll position, the chosen view mode (`pendingMode` + `explorer_ui` prefs), a running load (`FolderLoader` generation) and the thumbnail / folder-count caches (`ThumbMemory`, `FolderCountMemory` are process-wide) all survive; the empty / error card (`StateCardView`, at most 420dp wide through `MaxWidthLinear`) re-measures by itself and does not rebuild for the same face; Win11 dialogs are capped at 420dp. Fixed:
  - **Grid gaps wrong after rotation:** `GridGap` offsets depend on the column of a cell (`spanIndex`, `gridCols`), but `RecyclerView` caches the decoration insets of rows that stay attached, so after the column count changed some cells kept the old left / right gap. `updateColumns` now calls `recycler.invalidateItemDecorations()` right after the new span count.
  - **Scroll position on a column change:** before the span count changes, the first visible item and its offset are remembered, and `scrollToPositionWithOffset` puts the user back there (only while the grid manager is the active one; a mode switch keeps its own "first item stays first" rule from 4.7). The change is logged: `ExplorerUi: config: columns A -> B (list Npx, grid|large, keep item P)`.
  - **Skeleton and rotation during a load:** the layout-change listener of the list only watched the **width in Grid / Large mode**. Now it also watches the **height**, and it works in **List mode** too, so the shimmer skeleton refills the new height (`fillHeightPx`, which re-measures the skeleton) and the new width whenever the window changes while a folder is loading, in every mode.
  - **Address bar after a width change:** the breadcrumb row scrolls to the last crumb again (it used to keep the old scroll offset, so a narrower window could hide the current folder name).
  - **Fast-scroll thumb:** `FastScrollBar.onSizeChanged` redraws the thumb for the new height (before it waited for the next scroll event). A drag in progress while the window is resized keeps working (the drag fraction is mapped on the new height).
  - **Dark / light switch recreated the app:** `uiMode` was missing from the `MainActivity` `configChanges`, so changing dark / light mode destroyed and rebuilt the whole launcher (open windows, current folder, scroll, a running load were lost). `uiMode` is added and the duplicated `screenLayout` entry is removed: `orientation|screenSize|keyboardHidden|keyboard|screenLayout|smallestScreenSize|uiMode`. All colours of the explorer are fixed (`WX`), so nothing has to be redrawn for dark / light; `onConfigurationChanged` has a comment that says so.
  - **Important about the test:** `MainActivity` has `android:screenOrientation="portrait"`, so on a normal phone a rotation changes nothing. The width really changes in split-screen / free-form windows, on tablets and foldables (Android 16 and `targetSdk` 37 ignore the portrait lock on screens with a smallest width of 600dp or more), and in the unfolded state. ## Windows-style Quick Settings & Notification Center

A Quick Settings shortcut (gear / notification glyph) is added to the taskbar. It opens a Windows-inspired control panel with Wi-Fi and Bluetooth settings, Location, one Ring / Vibrate / Mute button, display/rotation settings, volume controls, Airplane Mode settings, flashlight toggle, Power Popup (Android 5.0+; requires enabling the app's Accessibility service), and a Windows 11 style notification center: live list of the phone's dismissible notifications grouped by app (app icon + name in a group header, rounded bordered cards with title, time and message), tap a card to open it, vector X to dismiss, collapse/expand arrow per app group, Show more / Show less when a group has more than 3, Clear per app and a Clear all pill (these dismiss on the phone too), and an empty state with a bell icon. Below the notifications sits a Win11-style calendar: today's full date, a month grid with the current day highlighted, and up/down arrows to change the month (tap the month title to jump back to today). All icons are vector drawables, no emoji. **Glass UI:** the panel uses a translucent theme (Theme.Win11.Glass) so the screen behind shows through, with real background blur on Android 12+ devices that support it, and frosted rounded tiles and cards with a thin light border. **Do Not Disturb:** the bell at the top of the notification section turns pop-ups and sounds off (the bell changes to a slashed bell and a note appears); notifications are still collected in the center. **Toast:** a new notification from any app slides in as a glass card at the top right with the app icon, name, sender and message, fades after 5 seconds, tap opens the notification center, X dismisses it. It needs Notification access to be turned on for the app.

Android security restrictions apply: Wi-Fi/Bluetooth/Location/Airplane Mode and rotation controls open the relevant system settings rather than silently changing protected system state. Screen recording works from the panel's recorder tile: Android's system screen-capture consent dialog appears first (it cannot be skipped), then the whole screen is recorded (optionally with microphone audio) and saved to Movies/RizwanS2; tap the tile again or the notification's Stop action to finish. Screenshot: with the "Win11 Power and Lock" Accessibility service enabled (Android 9+) it is a single tap; otherwise Android's system screen-capture consent dialog appears and a PNG is saved to Pictures/RizwanS2. Nothing is captured silently. The flashlight turns on at the brightest level the device reports (Android 13+ devices that expose torch strength); other devices use plain on/off. The tile reflects the real torch state.

## Quick Settings flyout (v2.1.0)

- **Windows 11 layout, docked to the right** just above the taskbar. **Notifications and calendar are on top, Quick Settings are at the bottom** (tiles, then brightness and volume sliders). There is no close button: tap anywhere outside the panel (or press Back) to dismiss it. The tray clock opens it (the taskbar gear is hidden).
- **Win11 sliders:** a brightness slider and a volume slider (tap the speaker icon to mute / unmute). The volume slider follows the hardware volume keys.
- **Tiles show real state** (accent fill when on): Wi-Fi, Bluetooth, Airplane, Location, Auto-rotate, Flashlight, one Ring / Vibrate / Mute button (tap to cycle), Screen recorder.
- **Settings are applied automatically where Android allows it:**
  - Brightness and Auto-rotate: allow **Modify system settings** once. The app asks, opens the right screen, and finishes the action when you come back.
  - Silent mode: allow **Do Not Disturb access** once (same flow).
  - Wi-Fi: switched directly on Android 9 and older; Android 10+ shows the system Internet panel (apps cannot toggle Wi-Fi there).
  - Bluetooth: switched directly up to Android 12L (asks for *Nearby devices* once); Android 13+ shows the system "turn on Bluetooth" prompt.
  - Location: switched directly once you run `adb shell pm grant com.srizwan.win11 android.permission.WRITE_SECURE_SETTINGS` a single time; otherwise it opens Location settings.
  - Airplane mode: opens the system screen (Android only lets system apps switch radios).
- **Start search fix:** with the keyboard open the Start panel now shrinks to the free space (search box stays visible) and turns more opaque while searching.
- **Glass everywhere:** the popup menus (Start / app long-press / Messages long-press) are now glass `GlassMenu` cards, the remaining system dialogs are `W11Dialog`, all search boxes (Start, Contacts, Messages, in-file search) use the same glass pill, and text fields inside dialogs are glass too. The text viewer is dark glass.

## Debug & crash log (v2.0.1)

The app now keeps its own log so problems can be diagnosed on the phone itself:

- **View it:** Quick Settings (tap the tray clock at the right of the taskbar) → *Debug log* tile → Refresh / Copy / Share / Clear.
- **File location:** `Android/data/com.srizwan.win11/files/logs/app.log` (rotates at 512 KB; `app.old.log` is the previous one).
- **Crashes:** any uncaught exception is saved and shown in a dialog the next time the app opens, with a button to open the full log.
- **Startup is fault-tolerant:** every startup step is guarded. If one screen (Files / Browser / Phone / Messages) fails to build, a small error panel replaces it and the rest of the app still opens. If the whole UI fails, an on-screen "Startup error" page shows the stack trace with *Open log* and *Retry*.
- Logcat tag prefix: `Win11/` (e.g. `adb logcat -s Win11/Main Win11/Quick Win11/CRASH`).

## Glass UI and vector icons (latest)

- **No emoji anywhere:** every emoji and symbol glyph used as an icon (phone, contacts, recent calls, torch, zip, download, warning, play/pause, close, refresh, settings, orientation buttons, etc.) is now a vector drawable (`ic_w_*`, plus the existing `ic_qs_*`) set through the `Ico.kt` helpers (`iconOnly`, `iconStart`). Toasts and list items that only had a leading emoji now show plain text. `W11Dialog.Builder.setIcon()` puts a vector icon before a dialog title.
- **Full glass look:** the main window draws the wallpaper bloom behind a translucent taskbar; the Start menu, search boxes, dialogs (frosted card, light border, blur behind on Android 12+ devices that support it), the Quick Settings / Notification panel, the Notification settings screen and the toast card all use translucent surfaces with a thin light border. Android 8.0 uses an opaque dark window instead of a translucent one (platform crash with locked orientation).

## Deep link (rizwans2://)

The launcher opens from links that use the custom scheme `rizwans2://` (no domain needed):

- `rizwans2://open` opens the desktop; `files`, `browser`, `sms`, `start` and `quick` open that screen (`dialer` opens the system Phone app) (e.g. `rizwans2://quick` opens Quick Settings; `rizwans2://calculator` opens the Calculator).
- Works from an HTML link (`<a href="rizwans2://open">`), another app, or `adb shell am start -a android.intent.action.VIEW -d "rizwans2://open"`.
- Plain browser address bars treat it as a search, so a typed `rizwans2://open` may not launch; use a link on a web page instead.

## Calculator (built-in)

A built-in **Calculator** app appears in All apps (and in Start > Recent once opened; you can pin it). Floating glass panel docked above the taskbar (like the Quick Settings flyout; tap outside it to close) with vector icons only, centered in their keys: digits, `+ - × ÷`, `%` (`200 + 10%` = 220), `±`, backspace (long-press = clear), `C`, `=`, a live result preview line, divide-by-zero error, and hardware-keyboard support. Code: `CalculatorActivity.kt`.

## Taskbar toggle, centered icons, glass Phone / Messages

- **Taskbar toggle (Windows 11 behaviour):** tapping a pinned taskbar app that is **not** open opens it; tapping the one that is **already in front** minimizes it back to the desktop (its state, e.g. an open conversation or browser tabs, is kept). Opening an app from the Start menu or the desktop never minimizes. Code: `Win11Shell.onMinimize` (set in `MainActivity`).
- **Centered icons:** icon-only buttons (and icon + text buttons with centered text) used to draw their vector icon at the left edge. `Ico.kt` now centers them (`iconOnly` / `iconStart` add a layout listener; wrap_content views are untouched). This fixes the Calculator keys and the Phone buttons (backspace, contacts, Call, call-back).
- **Glass Phone & Messages:** both screens were made translucent (the Phone screen is now hidden, see below) (glass bars, cards, keys with a thin light border and ripple; sent / received bubbles and the composer too) and the wallpaper bloom shows through behind them. The other sections keep their solid backgrounds.

## System Phone instead of the built-in Phone

- **Phone now opens the device's own Phone (dialer) app** from the taskbar Phone icon, the desktop Phone icon, the Start menu / All apps and `rizwans2://dialer`. The icon is unchanged: the same green built-in phone vector, in the taskbar, on the desktop and in Start (the system Phone app is listed as "Phone" with that icon).
- **The built-in Phone screen is hidden** (no entry in Start / All apps, no taskbar switch). Its code (`createDialerView`, recent calls, contacts picker) is kept in `MainActivity.kt` but is never shown.
- **Messages:** "Call" in a conversation (header phone button and the long-press menu) opens the system dialer with that number pre-filled (`ACTION_DIAL`, nothing is called until you press call there).
- **Existing installs:** if the built-in Phone was pinned in Start, that pin is moved to the system Phone app at the same position (a hidden built-in Phone becomes a hidden system Phone). The system Phone app is the device's default dialer (`TelecomManager.getDefaultDialerPackage`, falling back to whatever handles `ACTION_DIAL`).
- Since the Phone is an external app, it has no "running" dot on the taskbar and tapping its icon always opens it (the minimize toggle applies to Files, Browser and Messages).

## Start menu: Recent apps (Pinned only when you pin)

- **Recent is the default Start page.** Apps you open from Start (pinned grid, Recent grid, All apps or search) are remembered, most recent first (up to 12, 6 per row). Pinned and hidden apps are not repeated in Recent.
- **Pinned appears only when something is pinned.** Nothing is auto-pinned any more. Long-press an app in All apps > *Pin to Start* (or long-press a Recent app > *Pin to Start*) and a **Pinned** section shows above Recent; unpin the last one and it disappears again.
- **Long-press menus:** Recent app = Pin to Start, Remove from recent, Hide app, App info. Pinned app = Unpin from Start, Move to front, Hide app, App info.
- The **All apps ›** button sits on the first section header (Pinned if shown, otherwise Recent).
- **Existing installs:** one time only, a pinned list that is just the old auto-seeded defaults (Files, Browser, Phone, Messages, Notifications, Calculator, Chrome, Gmail, YouTube, Play Store, Settings, ...) is cleared; apps you pinned yourself outside that default set are kept.
- Code: `AppRepository.recent()/addRecent()/removeRecent()` in `StartApps.kt`; `refreshPinnedGrid()`, `showRecentMenu()` in `Win11Shell.kt`. Prefs key `start_menu/recent`.

## Messages: loading animation, pagination, read state

- **Loading animation:** the conversation list shows an accent-coloured spinner from the first frame until the first page is ready (no more blank pane on first open). Opening a conversation shows a spinner while its first page loads, and a small spinner row at the top while older messages load.
- **Pagination, 20 at a time:**
  - *Conversation list:* the first 20 conversations are shown (contact names are looked up only for the visible page); the next 20 load when you scroll near the bottom. A refresh keeps the pages already shown unless the search text changed.
  - *Conversation:* opens at the newest 20 messages, scrolled to the bottom like a chat app. Scrolling up near the oldest loaded message fetches 20 older ones; the view stays in place (no jump) and day separators are merged across pages. If the first page does not fill the screen, older pages are fetched automatically. The header shows "20+ messages" while more exist.
  - Queries use `date < oldest loaded` (not an offset), so new / sent messages do not cause duplicates. The old fixed 500-message cap is gone.
- **Read behaviour:** opening a conversation marks it read: the unread badge and bold text clear immediately and stay cleared; only messages that arrive later count as unread again. The SMS provider is updated too when this app is allowed to (default SMS app); otherwise a local per-conversation "read at" marker is used (`sms_ui` prefs, key `readat:<address>`).
- Code: `MainActivity.kt` (`smsQueryPage`, `smsLoadOlder`, `smsLoadMoreConversations`, `smsMarkRead`, `smsSpinner`).

## Per-app switches: Hide app and Black box (default opener)

- **Where:** Notifications > **Apps**. Every app row already had the pop-up notification on / off switch; below it each row now also has **Hide app** and **Black box (default opener)** switches (a tap anywhere on their line flips the switch). A small hint line under the "Apps" title names the three switches. Search, "Turn all on / off" (notifications only), the master switch and everything else on that screen are unchanged.
- **Long-press the device name** (the name + avatar in the Start menu footer, `Win11Shell.openAppSwitches()`) to open this screen scrolled straight to the **Apps** list (intent extra `NotificationSettingsActivity.EXTRA_FOCUS_APPS`). A normal tap on the device name still opens the Settings menu.
- **Hide app:** uses the same hidden list as the long-press "Hide app" in Start (`start_menu/hidden`, one `package/class` key per line), but per package: every launcher entry of the app is hidden and the app is removed from Pinned. It then appears under *Hidden apps* in All apps, where *Unhide app* brings it back (the switch follows that too). `AppRepository.reloadPrefs()` re-reads the pinned and hidden lists whenever Start opens (`load()`), so a change made in this screen shows at once.
- **Black box (default opener):** when on, a normal tap on the app in Start (Pinned, Recent, All apps, search) opens it in the BlackBox virtual space (`ParallelApps.open`), exactly like the long-press "Open in black box (parallel)": the copy is made the first time ("Preparing ... in the black box..."), later taps just start it. The app is still added to Recent. If the black-box copy cannot be started, an error toast shows and the real app is opened instead (`ParallelApps.open(..., onFail)`). Saved per package in `app_control` / `blackbox_default`.
- **Code:** new `AppControl.kt` (`isHidden / setHidden`, `isBlackBoxDefault / setBlackBoxDefault`); `NotificationSettingsActivity.kt` (row layout is now a vertical card: top line = icon, name, package, notification switch; below = the two new switches; `focusApps()`); `Win11Shell.kt` (`launchApp()` -> `openReal()`, long-press listener); `StartApps.kt` (`reloadPrefs()`); `ParallelApps.kt` (`onFail`).
- **Build fix (4.15):** `ExplorerUi.show(...)` in `FileExplorerUi.kt` is now `internal`, because it takes the `internal` type `FileItem` (Kotlin error "'public' function exposes its 'internal' parameter type argument").
